# 冷水坑_3 开发文档（总集 + 二次开发接口）

> 项目：冷水坑_3（直播/OBS 用比赛信息叠加系统）
> 引擎：Godot 4.5（Forward Plus，透明窗口）
> 语言：C#（核心逻辑）+ GDScript（场景编排/UI）
> 主场景：`res://scene/Main.tscn` → 节点 `Main`（Node2D）

---

## 1. 项目简介

冷水坑_3 是一套面向直播推流的「选手 / 解说信息叠加」工具。它从后端 API（`https://lskb.cc.cd`）拉取选手、解说员数据，登录后在控制面板选人、切换红蓝方模式、切换不同场景（主视觉 / 直播竞技场 / 等待 / ED / PK），并把选手信息自动派发到场景中任意位置的显示节点，最终通过 `OutputViewport` 以透明窗口 / 截图方式输出给 OBS。

核心能力：
- 账号登录 + 选手/解说数据拉取（带 CSRF、Cookie 维持）
- 本地缓存（无网络时仍可工作）
- 红/蓝双方选手「上台（stage）」与实时切换
- 场景热切换，且切换后自动重新套用当前模式与已上台选手
- **任意位置**的显示节点都能自动收到选手数据（自动发现机制，见 §6）

## 5. 信号链路（运行数据流）

```
登录/加载缓存
   └─ PlayerApiClient.players_loaded(data)
         └─ main.gd._on_players_loaded → PlayerManager.LoadPlayers(data)
               └─ PlayerManager.players_updated
                     └─ main.gd._on_players_updated → PlayerSelector.UpdatePlayerList()

用户在控制面板选人
   └─ PlayerSelector.player_selected(id)
         └─ main.gd._on_player_selected → update_player_displays(playerDict)
               └─ 派发到所有显示节点（见 §6）

用户点「上台（红/蓝）」
   └─ PlayerSelector → window.stage_player(id, side)
         └─ main.gd._on_stage_player → staged_red/blue_player_id = id
               └─ _apply_staged_players() → 按红/蓝路由派发

切换模式（红/蓝）
   └─ control_panel.mode_changed(mode)
         └─ main.gd._on_mode_changed → current_mode = mode
               └─ apply_mode_to_scene() + _apply_staged_players()

切换场景
   └─ control_panel.scene_selected(id) → scene_manager.transition_requested(id)
         └─ main.gd._on_transition_requested(id)
               ├─ 实例化新场景挂到 MainContentRoot
               ├─ _refresh_display_cache()   # 重新递归收集显示节点
               ├─ apply_mode_to_scene()
               └─ _apply_staged_players()     # 重新套用已上台选手
```

## 6. 二次开发接口（重点）

### 6.1 显示节点自动发现机制（最常用）

`main.gd` 在每次场景加载时，从场景根**递归遍历**整棵节点树，收集所有实现了下列方法的节点并缓存：

| 方法签名 | 用途 | 数据中转 |
|---|---|---|
| `Display(Godot.Collections.Dictionary)` | 选手显示 | 与 `DisplayPlayer` 等价 |
| `DisplayPlayer(Godot.Collections.Dictionary)` | 选手显示 | 同上 |
| `DisplayCommentator(Godot.Collections.Dictionary)` | 解说员显示 | 解说员数据 |

派发规则（`main.gd._apply_staged_players` / `update_player_displays`）：
- **节点名含 `Red` / 前缀 `r_` / 后缀 `_r`** → 收到红方选手
- **节点名含 `Blue` / 前缀 `b_` / 后缀 `_b`** → 收到蓝方选手
- **其余节点** → 收到「当前模式对应方」的选手（`current_mode == "Red"` 给红，否则蓝）

> 这意味着：你只要在任意场景的任意层级放一个实现了 `Display` / `DisplayPlayer` 的节点，并把子 Label 用 `[Export]` 拖好，它就会自动跟着选人/上台更新，**无需改动 `main.gd`**。

#### 模板 A：最小 C# 显示节点（推荐，可放任意位置）

```csharp
using Godot;

namespace PlayerStatistics
{
    public partial class PlayerDisplayTemplate : Control
    {
        [Export] public NodePath NamePath;
        [Export] public NodePath TeamPath;
        [Export] public NodePath RatingPath;

        private Label _name, _team, _rating;

        public override void _Ready()
        {
            _name = GetNodeOrNull<Label>(NamePath);
            _team = GetNodeOrNull<Label>(TeamPath);
            _rating = GetNodeOrNull<Label>(RatingPath);
        }

        // 方法名 Display → 被 main.gd 自动发现并分发
        public void Display(Godot.Collections.Dictionary player)
        {
            if (player == null || !player.ContainsKey("id"))
            {
                if (_name != null) _name.Text = "-";
                if (_team != null) _team.Text = "-";
                if (_rating != null) _rating.Text = "-";
                return;
            }
            string Get(string k, string f) => player.ContainsKey(k) ? player[k].ToString() : f;
            if (_name != null)   _name.Text   = Get("username", "-");
            if (_team != null)   _team.Text   = Get("team_name", "-");
            if (_rating != null) _rating.Text = player.ContainsKey("rating") ? player["rating"].ToString() : "-";
        }
    }
}
```

#### 模板 B：GDScript 版（最快，直接给节点加脚本）

```gdscript
extends Control

@onready var name_label = $NameLabel
@onready var team_label = $TeamLabel

func Display(player):
    if player == null or not player.has("id"):
        name_label.text = "-"
        return
    name_label.text = player.get("username", "-")
    team_label.text = player.get("team_name", "-")
```

#### 模板 C：固定显示某个选手（不跟选人，手动指定 id）

```csharp
using Godot;

namespace PlayerStatistics
{
    public partial class FixedPlayerDisplay : Control
    {
        [Export] public int FixedPlayerId = 1;

        private PlayerManager _pm;
        private PlayerDisplayTemplate _card;

        public override void _Ready()
        {
            _pm = GetTree().Root.GetNodeOrNull<PlayerManager>("Main/PlayerManager");
            _card = GetNode<PlayerDisplayTemplate>("Card");
            if (_pm != null)
            {
                _pm.Connect("players_updated", Callable.From(Refresh));
                Refresh();
            }
        }

        private void Refresh()
        {
            var dict = _pm.GetPlayerDictionary(FixedPlayerId);
            _card?.Display(dict);
        }
    }
}
```

### 6.2 选手数据字典字段

`GetPlayerDictionary(id)` / `Display(player)` 收到的 `Dictionary` 字段：

| key | 类型 | 含义 |
|---|---|---|
| `id` | int | 选手 id |
| `username` | string | 姓名 |
| `nickname` | string | 昵称 |
| `school` | string | 学校 / squad（= squad 别名） |
| `squad` | string | 分队（来自 `team.squad`） |
| `team_name` | string | 战队名 |
| `team_id` | int | 战队 id |
| `role` | string | 角色（`captain` / `member` 等） |
| `created_at` | string | 创建时间 |
| `operator` | string | 运营 / 操作者（来自 `team.operator`） |
| `roguelike` | string | 肉鸽模式（如 `sarkaz`，来自 `team.roguelike`） |
| `team_photo` | string | 队伍照片 URL（来自 `team.team_photo`） |
| `final_score` | int | 最终得分（来自 `team.final_score`） |
| `declaration` | string | 宣言 |
| `opening` | string | 开局词 |
| `rating` | int | 积分 |
| `wins` / `losses` / `draws` | int | 胜 / 负 / 平 |
| `avatar` | string | 头像 URL |
| `team_logo` | string | 队徽 URL（优先 `team.logo`，回退 `team.team_photo`） |

> 注：为避免解析遗漏，所有**未显式建模的字段**都会被原样保存到字典并随 `ToDictionary()` 一并带出（前向兼容）。`declaration` / `opening` 等附加字段会在选手对象或内嵌 `team` 对象中按多种命名（manifesto / motto / slogan / intro / bio / 宣言 / 开局 / opening …）自动探测。

解说员字典（`DisplayCommentator`）字段：`id`、`name`、`nickname`、`title`、`description`、`experience_years`。

### 6.10 现成零散控件（可自由摆放，无需编码）

`scene/ui/` 下提供两个已封装好的零散控件，可直接拖入任意 2D 场景、独立移动到任意位置，**每个实例只显示选手/队伍字典中的「一项」**。二者均以 `Node2D` 为根（与 `player_avatar.tscn` 同结构，根节点下挂单个子节点），并自动接入 §6.1 的显示节点自动发现机制（实现 `DisplayPlayer`，被 `main.gd` 自动派发数据）。

| 控件 | 场景 | 脚本 | 显示内容 |
|---|---|---|---|
| `PlayerFieldLabel` | `scene/ui/PlayerFieldLabel.tscn` | `scripts/ui/PlayerFieldLabel.cs` | 单个文本字段（Label） |
| `PlayerImageField` | `scene/ui/PlayerImageField.tscn` | `scripts/ui/PlayerImageField.cs` | 单张图片（TextureRect） |

#### PlayerFieldLabel（文本字段控件）
把 `PlayerFieldLabel.tscn` 拖入场景并定位后，在 Inspector 配置：

- `Field`（下拉）：要显示的字段，共 20 种 —— `Username`/`Nickname`/`School`/`Squad`/`TeamName`/`Rating`/`Wins`/`Losses`/`Draws`/`WinRate`(自动计算胜率)/`Role`(captain 显示为「队长」)/`Operator`/`Roguelike`/`FinalScore`/`Declaration`/`Opening`/`CreatedAt`/`TeamId`/`TeamPhoto` 等。
- `CustomField`：`Field = Custom` 时填写任意原始键（含 `team_xxx` 等 `_raw` 兜底字段）。
- `StaticLabel`：固定前缀（始终显示，不随数据变化），如 `"选手名："`.
- `Prefix` / `Suffix`：值的包裹文字，如前缀 `"运营："`.
- `Fallback`：数据缺失时显示（默认 `"-"`）。
- `AutoColor`：勾选后文字跟随红/蓝主题着色（`UpdateWithMode`）。

#### PlayerImageField（图片控件）
- `Kind`（下拉）：`Avatar`(头像) / `TeamLogo`(队徽) / `TeamPhoto`(队伍照片)。
- `UseTeamLogoAsFallback`：`Avatar` 模式下头像 URL 缺失时自动回退队徽。
- `TargetWidth` / `TargetHeight`：图片尺寸（默认 200×200，保持比例）。
- 复用 `AvatarLoader`：头像按 id 缓存、队徽/队照按 URL 缓存；GIF 自动取首帧；无网络时回退本地缓存。

#### 使用要点
- 二者都通过 `DisplayPlayer(dict)` 接入自动发现，**无需改 `main.gd`**。
- 节点名含 `Red`/`Blue`（或前缀 `r_`/`b_`、后缀 `_r`/`_b`）即锁定对应方；否则跟随 `current_mode`。
- 一个场景里可放任意多个实例，各自独立设置 `Field`/`Kind`，自由排布。示例：`RedName`(`Field=Nickname`) + `BlueAvatar`(`Kind=Avatar`) + `RedScore`(`Field=FinalScore`, `StaticLabel="最终分："`)。

## 7. 扩展指南

### 7.1 加一个自定义显示位置
1. 在目标 `*.tscn` 任意位置放一个 `Control`，挂 §6.1 的脚本。
2. 拖好内部 Label 的 `[Export]` 路径（GDScript 用 `@onready`）。
3. 节点名带 `Red`/`Blue` 锁定一侧，否则跟随模式。
4. 运行 → 选人/上台即自动更新，无需改其他代码。

> 不想写脚本？可直接用 §6.10 的现成零散控件（`PlayerFieldLabel` / `PlayerImageField`）：拖入场景、配置 `Field`/`Kind` 即可，无需编码。

### 7.2 加一个全新场景
1. 新建 `scene/your_scene.tscn`。
2. 在 `main.gd` 的 `scene_map` 增加 `"YourKey": preload("res://scene/your_scene.tscn")`。
3. 场景里放任意 `Display`/`DisplayPlayer` 节点即可被自动发现；切换进来时 `main.gd` 会重建缓存并重新套用模式与已上台选手。

### 7.3 加一个支持「换肤/模式」的组件
实现 `func UpdateWithMode(mode: String)`（GDScript）或 `public void UpdateWithMode(string mode)`（C#），`apply_mode_to_scene` 会递归调用它。同时可实现 `UpdateRedBlueVisibility` 风格逻辑（节点名带 Red/Blue 控制显隐，见 `toggle_red_blue_visibility`）。

### 7.4 接入新数据源
调用 `PlayerManager.LoadPlayers(dict)` 或 `CommentatorManager.LoadCommentators(dict)`，只要 `dict["players"]` 是数组、元素为含上表字段的字典即可；相同数据会被 `LoadPlayers` 的签名检测跳过，避免重复刷新。
