# 插件开发指南

演播室2 采用 **「一切皆插件」（Everything is a Plugin）** 架构：主核心（`core/`）只提供
引导、生命周期、服务总线与场景调度，**所有**可切换直播场景、控制面板、编辑器、数据源
都是插件。

> **本仓库已抽为纯核心**：原 `plugins/`（内置插件）与示例插件已全部移出，核心程序在
> 零插件时也能正常启动（仅提示无可装载面板）。所有插件——无论由谁开发——都以
> **外部插件**形式存放于 `mods/`（开发时放项目内，发行时放可执行文件同级）。

插件与核心**同构解耦**：同一份 `plugin.json`、同一套生命周期、同一条热重载管线。

---

## 1. 目录结构

```
mods/your_plugin/                # 每个插件是 mods/ 下一个独立文件夹
├── plugin.json                  # 清单（必需）
├── plugin.gd                    # 入口脚本：extends Plugin（必需）
├── scenes/                      # 场景资源（直播场景放这里）
│   └── live_scene.tscn
├── panels/                      # 控制面板 UI（可选）
├── scripts/                     # 其他脚本（可选）
├── assets/                      # 自有资源（必需，见「资源自携带」）
│   ├── textures/
│   ├── fonts/
│   └── shaders/
└── data/                        # 自有数据（可选）
```

> 提示：仓库历史上的最小范本 `mods/example_mod/` 与依赖演示 `mods/example_mod_child/`
> 已随纯核心化移出，完整内容保存在项目备份包中（见文末「参考实现」）。

## 2. 清单文件 `plugin.json`

```json
{
    "id": "your_plugin",
    "name": "你的插件",
    "version": "1.0.0",
    "author": "你的名字",
    "description": "一句话简介",
    "api_version": "2.0.0",
    "dependencies": [],
    "load_priority": 0,
    "hot_reload": { "enabled": true, "mode": "auto", "debounce_ms": 300 },
    "watch": ["scenes/", "scripts/", "data/"],
    "provides": {
        "scenes": [
            {
                "id": "your_live_scene",
                "name": "你的直播场景",
                "type": "live",
                "scene": "scenes/live_scene.tscn",
                "description": "这个场景在直播中显示什么"
            }
        ],
        "panels": [
            {
                "id": "your_panel",
                "name": "你的面板",
                "scene": "panels/panel.tscn",
                "slot": "right",
                "order": 10
            }
        ]
    }
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | String | 插件唯一标识，建议与文件夹名一致 |
| `name` / `version` / `author` / `description` | String | 展示信息 |
| `api_version` | String | 兼容的内核契约版本（当前 `2.0.0`） |
| `dependencies` | Array | 依赖的其它插件 id；缺失或成环会导致本插件**阻塞不加载**，见第 5 节 |
| `load_priority` | int | 初始化顺序，数值越小越早 |
| `hot_reload.enabled` | bool | 是否参与自动热重载 |
| `hot_reload.debounce_ms` | int | 变更去抖时长（毫秒，默认 300） |
| `watch` | Array | 参与热重载监听的子目录（缺省 `scenes/ scripts/ panels/ data/`） |
| `provides.scenes` | Array | **可切换场景**列表，见下 |
| `provides.panels` | Array | 注入控制面板的**面板**，见下 |

### `provides.scenes` 条目

| 字段 | 说明 |
|------|------|
| `id` | 场景唯一标识，切换时使用，需全局唯一 |
| `name` | 显示名称（出现在控制面板「直播场景」导航中） |
| `type` | `live` / `overlay` / `ui`，直播场景用 `live` |
| `scene` | 场景文件路径，相对插件目录 |
| `description` | 悬停提示 |

### `provides.panels` 条目

| 字段 | 说明 |
|------|------|
| `id` | 面板唯一标识 |
| `name` | 显示名称 |
| `scene` | 面板场景路径，相对插件目录 |
| `slot` | 装载槽位：`main_window`（主窗口）/ `editor`（编辑器）/ 自定义 |
| `order` | 同槽位内的排序权重 |

> 内核只认识"能力"，不认识具体插件；`PluginManager` 会把 `scenes`/`panels` 中的相对路径
> 解析为 `res://` 绝对路径后注册到 `SceneDirector` 与 `PluginRegistry`。

> 兼容性：旧的 `mod.json` 仍可被解析，`streaming_scenes` 会自动映射为
> `provides.scenes[type=live]`。新插件请统一使用 `plugin.json`。

## 3. 入口脚本 `plugin.gd`

继承 `Plugin`（`core/plugin.gd`），按需重写生命周期回调：

```gdscript
extends Plugin

func get_metadata() -> Plugin.PluginMetadata:
	var m := Plugin.PluginMetadata.new()
	m.id = "your_plugin"
	m.name = "你的插件"
	return m

# 生命周期（按需重写）
func on_load() -> bool: return true        # 加载：注册资源，勿做重活；返回 false 会中止加载
func on_enable() -> void: pass             # 启用：注册能力、连接信号
func on_disable() -> void: pass            # 禁用：断开信号、注销能力
func on_before_reload() -> void: pass      # 热重载前：保存状态
func on_after_reload() -> void: pass       # 热重载后：恢复状态
func on_unload() -> void: pass             # 卸载：释放资源
```

## 3.1 跨插件事件（EventBus）

插件间广播 / 通知走内核事件总线（`Kernel.event_bus`），事件名**一律引用 `EventCatalog`
常量**（禁裸字符串）；订阅必须带 owner（插件 id）——插件卸载 / 热重载时内核会自动清理
该插件的全部订阅，**无需在 `on_disable` 手动退订**：

```gdscript
func on_enable() -> void:
    var bus := get_event_bus()   # PluginContext 访问层（ADR-0001）；或 self.context.event_bus
    if bus == null:
        return
    # 订阅：回调只收 payload 字典；owner 传本插件 id
    bus.subscribe(EventCatalog.DATA_RELOADED, _on_data_reloaded, &"your_plugin")

func _on_data_reloaded(payload: Dictionary) -> void:
    print("[your_plugin] 数据重载: ", payload.get("scope", ""))
```

- 发布：`get_event_bus().emit_event(EventCatalog.某事件, {"字段": 值})`；
  payload 字段契约写在 `core/event_catalog.gd` 注释中，新事件先登记目录。
- debug 构建下 `emit_event` 会校验事件名已登记（未登记输出警告），release 跳过校验。
- 类型化信号（`player_changed` / `scene_changed` 等）保留向后兼容；
  **新代码统一走 `subscribe` / `emit_event`**。

## 4. 直播场景：继承 `PluginScene`

直播场景根节点脚本应 `extends PluginScene`（`core/plugin_scene.gd`），
即可自动获得身份信息与当前直播数据。

```gdscript
extends PluginScene

@onready var name_label: Label = $NameLabel

func _on_scene_enter() -> void:
	# 场景进入：用 scene_name / scene_id / plugin_id 做初始化
	name_label.text = scene_name
	_refresh(get_current_player())

func _on_scene_exit() -> void:
	# 场景退出：释放临时资源
	pass

func _on_player_changed(player_data: Dictionary) -> void:
	_refresh(player_data)

func _refresh(player_data: Dictionary) -> void:
	name_label.text = str(player_data.get("name", "未选择"))
```

### PluginScene 提供的接口

| 成员 | 说明 |
|------|------|
| `plugin_id` / `scene_id` / `scene_name` | 由 SceneDirector 注入的身份信息 |
| `_on_scene_enter()` | 场景进入回调（重写） |
| `_on_scene_exit()` | 场景退出回调（重写） |
| `_on_player_changed(data)` | 当前选手变化回调（重写） |
| `_on_announcer_changed(data)` | 当前解说变化回调（重写） |
| `get_current_player()` | 当前选手数据 |
| `get_current_announcer()` | 当前解说数据 |
| `get_players()` / `get_teams()` | 全部选手 / 队伍列表 |
| `get_team_by_id(id)` | 按 id 取队伍 |
| `player_changed` / `announcer_changed` | 可连接的信号 |

> 旧接口 `ModScene` / `_on_mod_scene_ready()` / `mod_id` 仍作为兼容别名可用，但新代码请使用上表。

### 资源自携带（重要约定）

每个插件**必须自带全部依赖资源**（纹理、字体、着色器等），放在插件目录的
`assets/` 下。核心不提供任何共享资源——插件目录必须可以整体搬移、独立分发。

- **`.tscn` 场景**：`ext_resource` 一律使用**相对路径**（相对场景文件所在目录），
  例如 `../assets/textures/bar.png`。这是插件目录可移植的基石。在 Godot 编辑器内
  保存场景会自动生成相对路径；若手工调整，请同时删除资源条目上的
  `uid="uid://..."` 属性（uid 绑定原项目，搬移后失效反而报错）。
- **脚本内加载**：以脚本自身位置为基准拼接，`res://`（编辑器内）与导出后的真实
  目录均可用：

  ```gdscript
  # 注意：get_script() 返回 Variant，必须显式声明 String 类型
  var avatar_path: String = (get_script().resource_path.get_base_dir()
      .path_join("../assets/textures/default_avatar.png") as String).simplify_path()
  ```

- **禁止硬编码** `res://plugins/...` 或 `res://mods/...`：导出后插件位于**可执行文件
  同级目录**（真实文件系统，不在 `res://` 内），此类路径无法解析。场景 / 面板路径
  一律在 `plugin.json` 中以**相对插件目录的相对路径**声明，由加载器解析为绝对路径。
- 需要 `Image.load_from_file()` 直接读图片文件时，同样以脚本位置为基准拼接
  绝对路径。
- 直播画面基准分辨率为 1920×1080，场景坐标系可用绝对定位。

## 5. 依赖解析（mod 依赖 mod）

`plugin.json` 的 `dependencies` 声明本插件依赖的其它插件 id。`PluginManager`
在扫描完所有清单后进行**强制解析**：

| 情形 | 结果 |
|------|------|
| 依赖全部就绪 | 按拓扑序加载：先依赖、后依赖方 |
| 依赖缺失（id 不存在） | 本插件**阻塞不加载** |
| 依赖自身被阻塞（传递阻塞） | 连带阻塞，直到依赖恢复 |
| 环形依赖 | 环上**所有**插件均阻塞 |

- **无半加载**：被阻塞的插件不会执行 `on_load`，也不会注册任何场景 / 面板能力。
- **加载顺序**：拓扑排序；同层按 `load_priority` 升序、再按目录名稳定排序。
- **级联重载**：热重载某插件后，所有直接 / 间接依赖它的插件会自动级联重载，
  保证依赖方重建时引用的是新版本。
- **补加载**：执行「重载全部插件」（F5）时，会在拓扑序尾部尝试补加载先前被阻塞的
  插件——把缺失的依赖插件放回 `mods/` 后按 F5 即可，无需重启。
- 控制面板「模组管理」会列出被阻塞插件及其原因（缺失依赖 / 循环依赖）。

> 设计约束：依赖只表达「必须先于我加载 / 启用」，不含版本范围语义。声明依赖前请
> 确认对方插件确实存在于 `mods/`。

## 6. 加载、启用与调试

1. 把插件文件夹放进插件根目录：
   - **开发（编辑器内）**：项目内 `mods/`；
   - **导出后（分发给用户）**：可执行文件同级的 `mods/`（该目录不会被打包进程序）。
   `PluginManager` 会**自动扫描**带 `plugin.json` 的目录，无需任何注册表文件。
2. 启动程序，控制台会输出 `[PluginManager] 插件已加载并启用: your_plugin`。
3. 提供 `type=live` 场景的插件会出现在控制面板导航区，点击即可切换；
   `slot` 面板会按槽位自动装载。

## 7. 热重载

修改插件后**无需重启**即可生效。内核通过 `FileWatcher` 轮询插件 `watch` 路径
（Godot 运行时没有 OS 级文件监听 API），发现变更后经 `debounce_ms` 去抖并重载对应插件。

### 触发方式

| 方式 | 操作 |
|------|------|
| 自动（轮询） | 修改 `watch` 路径下的文件，默认开启 |
| 手动·全局 | 快捷键 `F5`，或控制面板「重载全部插件」按钮 |
| 手动·单插件 | 控制面板模组列表中的「重载」按钮 |
| 开发模式 | 启动参数 `--plugin-hot-reload`（强制开启并输出详细日志） |

### 重载管线（单插件）

```
检测到变更 ─▶ 去抖合并 ─▶ on_before_reload
   ├─ 1. 脚本重载：GDScript.reload()（有存活实例的脚本会跳过，尽力而为）
   ├─ 2. 注销旧能力（场景 / 面板）
   ├─ 3. 卸载旧入口实例
   ├─ 4. 从磁盘重新加载（绕过资源缓存，读取最新 .tscn / .json）
   ├─ 5. 重新注册能力，刷新 PluginRegistry
   ├─ 6. 若当前场景由该插件提供 → SceneDirector 原位重建（先构建后替换）
   └─ ▶ on_after_reload，广播 plugin_reloaded / data_reloaded
```

### 能力边界（诚实声明）

| 变更内容 | 是否支持 | 说明 |
|---|---|---|
| 场景 / 纹理 / 字体 / `.tscn` | ✅ 运行时可热重载 | 重新实例化即可 |
| 数据 `.json` | ✅ | 清缓存重读并广播 |
| 已运行节点上的脚本逻辑 | ⚠️ 尽力而为 | 依赖 `GDScript.reload()`；有存活实例时跳过，建议配合 F5 或重启 |
| 全局单例脚本签名变更 | ⚠️ 需整插件 reload | 会重建插件实例 |
| 导出后的模板 / 引擎级改动 | ❌ 需重启 | 引擎限制 |

> 在 **Godot 编辑器**内运行时，编辑器自带的脚本重载会叠加生效，体验最佳。

### 失败保护

- **先构建、后替换**：新场景实例构建成功后才销毁旧实例，重载失败**不会黑屏**。
- 清单缺失 / `on_load` 失败时**回滚**旧场景与能力注册，插件置 `ERROR`，不中断其它插件。

## 8. C# 框架 `framework_cs/` 集成

### 8.1 现状与定位（先读）

`framework_cs/` 是一套**独立的通用内容框架**（实现语言为 C#），提供内容包体系
（players / teams / selections / game_rules）、加载、校验、配置与扩展点：

```
framework_cs/
├── Core/FrameworkCore.cs            # 入口节点：LoadDefaultContent / GetFrameworkInfo ...
├── Content/ContentSchema.cs         # 内容 schema 定义（SCHEMA_VERSION = "1.0"）
├── Content/ContentLoader.cs         # 内容加载（SetContentBasePath / LoadAllContent）
├── Content/ContentRegistry.cs       # 内容注册表（RegisterPlayer / GetAllPlayers / GetStats）
├── Config/ConfigManager.cs          # 配置管理（GetFrameworkConfig / LoadFrameworkConfig）
├── Validation/ContentValidator.cs   # 内容校验（ValidatePlayer / ValidateContentDirectory）
└── Extensions/ExtensionInterface.cs # 扩展点（RegisterExtension / CustomGameRules ...）
```

> **重要**：该框架**目前尚未接入插件系统**——
> - 项目未生成 `.csproj` / `.sln`，`framework_cs/` 的 `.cs` **未被编译**；
> - 未注册为 autoload；
> - `PluginManager` 只识别 GDScript 入口（`plugin.gd` / `mod.gd`）。
>
> **架构决策**：**C# 插件本期保持独立、后续单独评估**，
> 契约层已预留 `api_version` 以兼容未来扩展。
> 因此**目前不支持纯 C# 插件入口**（`.cs` 不会被 `PluginManager` 加载）。

### 8.2 推荐桥接策略：GDScript 外壳 + C# 服务

插件入口与直播场景仍用 GDScript（`extends Plugin` / `extends PluginScene`），
C# 侧作为**服务层 / 算法层**被调用。这样**无需改动内核**，且与 `provides` 清单、
热重载管线完全兼容。

职责划分建议：

| 层 | 语言 | 负责 |
|---|---|---|
| 表现与交互 | GDScript | 场景、UI、动画、热重载（易变） |
| 内容与规则 | C# | 内容包加载、校验、计分/规则算法、扩展点（稳定） |

### 8.3 启用步骤

1. 使用 **.NET 版** Godot（本项目为 `4.6.3.mono`，`project.godot` 已含
   `[dotnet] assembly_name="演播室2"`）。
2. **生成 C# 工程以编译 `framework_cs/`**：在 Godot 编辑器执行
   `项目 > 工具 > C# > 创建 C# 解决方案`（生成 `.csproj` / `.sln`。
   若默认未包含框架目录，可在 `.csproj` 显式添加
   `<Compile Include="framework_cs/**/*.cs" />`），随后 `dotnet build`。
3. **注册服务**：把 `FrameworkCore`（`Node`）挂载为 autoload 节点，
   或作为子节点实例化，供 GDScript 通过 `get_node("/root/FrameworkCore")` 访问。
4. **在插件中调用**：

```gdscript
# plugin.gd —— GDScript 外壳桥接 C# 服务
extends Plugin

var _core = null

func on_enable() -> void:
	_core = get_node_or_null("/root/FrameworkCore")
	if _core == null:
		push_warning("[your_plugin] FrameworkCore 未挂载，跳过 C# 内容层")
		return
	# 调用 C# 方法：名称保持 C# 原始 PascalCase
	var ok: bool = _core.LoadDefaultContent()
	# 读取 C# 属性 / 返回值：Godot Variant 与 Dictionary 直接互通
	var info: Dictionary = _core.GetFrameworkInfo()
	print("[your_plugin] C# 内容加载: ", ok, " 信息: ", info)

func on_unload() -> void:
	_core = null
```

### 8.4 互操作要点

- **方法 / 属性**：从 GDScript 调用 C# 成员时**沿用 C# 原始命名（PascalCase）**，
  如 `_core.LoadDefaultContent()`、`_core.ContentRegistry`。
- **数据传递**：C# 的 `Godot.Collections.Dictionary` / `Array` 与 GDScript 的
  `Dictionary` / `Array` 为同一 Variant 类型，可直接互传。
- **信号**：优先改用 C# 方法回调；若使用 C# `[Signal]`，请在编辑器补全中确认
  GDScript 侧的实际名称后再 `connect`。
- **对象生命周期**：`RefCounted` 由引用计数管理；`Node` 需显式加入场景树。
  `ExtensionInterface.RegisterExtension` 接受 `Godot.Object` 处理器，
  务必在 GDScript 侧持有引用，避免被提前回收。
- **生命周期对齐**：在 `Plugin.on_enable / on_before_reload / on_after_reload / on_unload`
  中同步调用 C# 侧的注册与注销，保证两侧状态一致。
- **扩展点映射**：`ExtensionInterface.ExtensionType`（`CustomGameRules` /
  `CustomValidator` / `CustomRenderer` / `CustomSceneFactory` / `CustomImporter`）
  可与插件能力对应——用 C# 实现规则/校验/渲染，由 GDScript 插件在 `on_enable` 时注册。

### 8.5 与热重载的关系（重要边界）

- **C# 程序集无法运行时热重载**：修改 `.cs` 后需重新 `dotnet build` 并**重启应用**。
  插件热重载（F5 / 轮询）只覆盖 **GDScript、场景与数据**。
- 因此建议**把易变的场景 / UI 放在 GDScript 插件层，把稳定的内容 / 算法 / 校验放在 C# 层**，
  即可同时获得热重载体验与 C# 的工程化能力。

### 8.6 若要支持纯 C# 插件入口（需改内核，非本期范围）

当前限制来自：`PluginManager._instantiate_entry` 仅匹配 `plugin.gd` / `mod.gd` / `<id>.gd`，
且要求 `script is GDScript`。若需支持 `.cs` 入口，需要：

1. 让加载器接受 `CSharpScript` 入口；
2. 为契约提供 C# 基类，或允许 C# 继承 GDScript 全局类 `Plugin` / `PluginScene`；
3. 登记该变更并升级 `api_version` 兼容策略（同步本指南与 AGENTS.md）。
