# Git 工作规范（分支 · 提交 · 协作）

> 目标：单人 + AI 协作模式下，避免冲突与意外覆盖，保证 main 随时可用。
> 配套阅读：[`../AGENTS.md`](../../AGENTS.md)（AI 工作规范）。

---

## 1. 分支模型

| 分支 | 用途 | 规则 |
|------|------|------|
| `main` | **稳定线**：可运行、可导出的状态 | 只接收已验证的改动；禁止 force push |
| `feature/<主题>` | 新插件、内核接口改动、跨多文件重构 | 开发与试错在此进行，验证通过后并入 main |
| `fix/<问题>` | 针对某个明确 bug 的修复 | 修复验证后并入并删除 |

**何时必须开分支**（其余情况允许 main 直推）：
- 改动 `core/` 内核任何文件；
- 一次涉及 3 个以上插件目录；
- 试验性质、可能回滚的改动。

**main 直推的准入条件**：无头冒烟通过 + 日志无 ERROR + 改动范围与声明一致。

> 远程：`origin = https://github.com/Attenna/Arknights-Theurgy-Cup-Like-Streaming-Assistant.git`。
> 开始工作前先 `git pull`（尤其当多台机器 / 多个 Agent 轮流操作时）。

## 2. 提交信息规范

格式：`<类型>：<中文摘要>`（沿用仓库现有风格，如 `P7 控制面板：…`、`文档：…`、`修复：…`）。

| 类型 | 含义 |
|------|------|
| `P<n> <主题>` | 阶段性里程碑（如 `P7 控制面板：…`），一个阶段一个编号 |
| `插件` | 新增/修改某个插件 |
| `内核` | core/ 或引导壳改动 |
| `修复` | bug 修复 |
| `文档` | 仅文档 |
| `清理` | 删除遗留代码/资源 |
| `构建` | 导出配置、.gitignore 等工程配置 |

**要求**：
1. 一次提交只讲一个主题——**内核、插件、文档分开提交**（参考 `P7` 系列的拆分）。
2. 摘要写"做了什么 + 为什么"，不超过一行；细节留给文档与 diff。
3. 禁止 `git add -A` 盲提：按文件/目录明确 add，防止把 `.godot/`、构建产物、备份
   zip 等误入库（`.gitignore` 已覆盖，但新增文件类型时注意核对 `git status`）。

## 3. 提交前检查清单

- [ ] 无头冒烟通过（`--import` + `--quit-after 300`），日志无 ERROR / SCRIPT ERROR
- [ ] `git status` 中没有预期外的文件（尤其 `.godot/`、`*.zip`、`builds/`）
- [ ] 改动了约定/接口时，`framework/docs/` 对应文档已同步
- [ ] 插件改动：新资源已 `--import` 生成 `.import` 并一并提交（`.import` 与 `.uid` 随源文件入库）

## 4. 冲突与覆盖预防

1. **高频区与低频区分离提交**：`core/`（低频、高影响）与 `mods/<某插件>/`（高频）
   不放同一提交，回滚时互不牵连。
2. **一个插件目录同一时间只在一个分支/会话中修改**：插件目录是天然的冲突单元，
   跨分支并行改同一插件几乎必然冲突。
3. **改动内核前**：`git pull` → 声明影响面 → 单独分支 → 验证后合并。
4. **删除是显式决定**：删除插件/资源前打备份 zip（见 AGENTS.md 第 7 节），
   并在提交信息中注明去向（如"内容已归档备份"）。
5. **恢复历史文件**：从 git 历史（`git show <commit>:<path>`）或备份 zip 提取时，
   注意历史版本可能**早于最新改造**（例：git 里的 builtin_streaming_arena 是资源
   自携带改造前的旧版）——先核对内容再入 `mods/`。

## 5. 禁止事项

- ❌ `git push --force` 到 main（任何理由都不行，需要重写历史时先在本地确认并征得监督者同意）
- ❌ 提交 `.godot/`、`builds/`、`*.zip`、`.trae/`（.gitignore 已覆盖，新增类型时核对）
- ❌ 跳过验证直接提交"应该能跑"的改动
- ❌ 在一次提交里混合多语言内容（提交信息统一中文）

## 6. 版本与备份约定

- **内核契约版本**：`plugin.json` 的 `api_version`（当前 `2.0.0`）。内核接口变更时
  必须评估兼容性并升级策略，同步 [插件开发指南.md](插件开发指南.md)。
- **备份 zip**：重大删除/重构前打包到 `d:\Projects\Arknights-Streaming-Assistant_backup_<日期>.zip`
  （排除 `.godot/`、`builds/`）。备份是设计源的最终兜底（仓库内的 `.afphoto` 只保留必要份）。
- **发布**：按 [导出指南.md](导出指南.md) 导出 exe+pck，插件目录随 `{exe}/mods/` 分发，
  导出产物永不入库。
