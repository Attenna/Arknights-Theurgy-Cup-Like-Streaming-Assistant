# ADR-0003：契约测试框架选型（issue #5 / #6 前置）

状态：**待评审** ｜ 关联：[架构演进路线.md](../架构演进路线.md) 阶段 2、issue #5、issue #6 ｜ 日期：2026-10-13

## 背景

阶段 2 需要自动化测试支撑：

- issue #5：EventBus payload 校验 + EventCatalog 每个事件的 payload 契约测试用例；
- issue #6：协作集成测试（热重载 N 次订阅数守恒、依赖阻塞不加载），需真实引擎环境；
- issue #4（已关闭，3b66724）：验收项「契约测试跑通（players.json / teams.json 示例）」待测试框架落地后补齐。

仓库当前无任何测试基建，需先选型：**gdUnit4 第三方框架** vs **轻量自研 runner**。

## 方案 A：gdUnit4（第三方框架）

- 做法：`addons/gdUnit4/` 提交进仓库（或 CI 拉取），测试放 `tests/`，本地编辑器面板 / 命令行运行，CI 用官方 GitHub Action。
- 优点：断言 / 报告 / 参数化 / 场景测试能力成熟；社区维护；CI 集成现成。
- 缺点：引入外部 addon，与「纯核心、零第三方依赖」的仓库哲学相悖；`addons/` 目录与导出排除规则、CI 拉取逻辑都要新增；对当前需求（纯逻辑契约断言 + 引擎环境集成冒烟）大部分能力闲置；升级跟随维护成本。

## 方案 B：轻量自研 runner（推荐）

- 做法：新建 `tests/` 目录：
  - `tests/run_tests.gd`：`extends SceneTree` 入口（`--headless -s tests/run_tests.gd`，本会话已实测可跑）；
  - 断言 helper 极简（`assert_eq` / `assert_true` + 失败收集 + 计数），失败退出码 1，CI 直接判失败；
  - 单元测试：直接 `load()` 被测脚本实例化——DataSchema 校验 / 迁移、EventCatalog 登记全集、EventBus subscribe/unsubscribe_all 计数均为纯逻辑，无场景依赖；
  - 集成测试（#6）：真实无头启动（完整 autoload + 插件加载路径），经启动参数或独立测试场景触发 PluginManager 热重载与依赖阻塞用例，断言后以退出码收尾。
- 优点：零依赖、行为完全可控、贴合仓库最小化哲学；`-s` 链路已实测（DataSchema 校验/迁移全链路跑通）。
- 缺点：断言与报告自建自维护（量小）；无可视化报告。

## 影响面

- 新增 `tests/` 目录（#5 单测、#6 集成测试、#4 补充契约测试均在此）；
- `export_presets.cfg` exclude_filter 追加 `tests/*`（避免测试脚本进 pck；属核心导出配置小改，实施时单独说明）；
- `mods/_test_pair_a` / `_test_pair_b` 测试插件对（`export_mods.ps1` 已排除 `_` 前缀目录，无需改）；
- `.github/workflows/ci.yml` 追加测试步骤（workflow 推送需带 workflow 权限的 PAT，届时向用户索取）。

## 备选被否

- GUT：同为第三方 addon，gdUnit4 的替代项，同样引入外部依赖，无额外优势。
- 纯 CI 脚本 grep 式检查（无引擎执行）：测不出运行时行为（校验逻辑、订阅计数、热重载），只能查字面量，不满足 #5/#6。

## 验收

评审通过后：落地 runner → 实施 #5 payload 校验 + 契约测试（含补齐 #4 验收项）→ 关闭 #5 → 实施 #6 集成测试 → 关闭 #6。
