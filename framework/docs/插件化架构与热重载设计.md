> 状态：**待审批**（审批通过后进入开发）
> 目标版本：core 2.0.0
> 关联文档：[模组开发指南.md](./模组开发指南.md)、[STRUCTURE.md](../../STRUCTURE.md)

---

## 1. 背景与目标

当前架构已经有一个"半成品"模组系统（`core/mod_loader.gd` 等），但它与主程序是**两套并行逻辑**：

- 内置直播场景（主视觉 / 比赛场 / 候场页）由 [main.gd](../../src/scripts/main/main.gd) 硬编码在 `scene_map` 里；
- 模组直播场景走 `ModLoader`，是一条独立支线；
- 场景切换按钮在 [scene_manager.gd](../../src/scripts/main/scene_manager.gd) 里硬编码三个 ID。

本次改造要把它统一为单一范式：**一切皆插件（Everything is a Plugin）**，并在此基础上加入**热重载**。

### 目标

1. **统一契约**：内置直播场景、模组直播场景、控制面板、编辑器、数据源，全部实现同一个「插件契约」。
2. **极薄内核**：主核心只负责 *引导 / 生命周期 / 服务总线 / 场景调度*，不承载任何业务场景。
3. **内置场景插件化**：主视觉、比赛场、候场页从 `src/` 迁出，改为随程序分发的**内置插件**。
4. **热重载**：插件（场景 / 资源 / 数据）修改后无需重启即可生效；脚本层尽力而为并明确边界。

### 非目标（本期不做）

- 插件沙箱 / 安全隔离（GDScript 无内存隔离能力）。
- 在线插件市场 / 网络分发。
- C# 插件（`framework_cs/` 暂保持独立，后续单独评估）。

## 2. 现状梳理

| 关注点 | 现状 | 问题 |
|---|---|---|
| 场景注册 | `main.gd` 用 `preload` 常量 + `scene_map` 字典 | 新增内置场景要改核心代码 |
| 场景切换 | 递归找 `transition_requested` 信号 | 机制可用，但来源 ID 硬编码 |
| 模组加载 | `ModLoader` autoload | 与内置场景双轨，能力不统一 |
| 契约 | `ModInterface` + `ModScene` | 只服务"模组"，内置场景不遵守 |
| 热重载 | 无 | 改一个场景要重启整个程序 |
| 数据 | `AppData.get_exe_dir() + /userdata/*.json` | 散落的路径拼接，无统一服务 |

## 3. 目标架构总览

```
┌──────────────────────────────────────────────────────────┐
│  Kernel（主核心 · 唯一保留）                              │
│  ┌───────────────┐  ┌────────────────┐  ┌───────────────┐ │
│  │ PluginManager │  │ SceneDirector  │  │  EventBus     │ │
│  │ 生命周期/热重载 │  │ 场景注册/切换   │  │  全局信号      │ │
│  └───────────────┘  └────────────────┘  └───────────────┘ │
│  ┌───────────────┐  ┌────────────────┐  ┌───────────────┐ │
│  │ DataService   │  │ FileWatcher    │  │ PluginRegistry│ │
│  │ userdata 读写  │  │ 轮询变更检测    │  │ 能力/ID 索引   │ │
│  └───────────────┘  └────────────────┘  └───────────────┘ │
└──────────────────────────────────────────────────────────┘
              ▲ 统一契约 Plugin / PluginScene
   ┌──────────┴───────────┬──────────────────┬───────────────┐
   │ plugins/（内置，随包） │ mods/（第三方）    │ 未来：市场      │
   ├──────────────────────┼──────────────────┼───────────────┤
   │ builtin_main_vision   │ example_mod       │ ...           │
   │ builtin_streaming_... │ your_mod          │               │
   │ builtin_waiting_scene │                   │               │
   │ builtin_control_panel │                   │               │
   └──────────────────────┴──────────────────┴───────────────┘
```

**核心原则**

- 内核**不知道**任何具体场景的存在，只认识"插件"和"能力（capability）"。
- 内置插件与第三方插件**同构**：同一份 `plugin.json`、同一套生命周期、走同一条热重载管线。
- 唯一区别：内置插件随包分发（`plugins/`），第三方由用户安装（`mods/`）。

## 4. 主核心（保留内容）

内核 = `core/` 目录，仅包含下列职责，**不含任何业务场景**。

| 模块 | 路径 | 职责 |
|---|---|---|
| Kernel | `core/kernel.gd` | autoload 入口；初始化服务、扫描并启动插件 |
| PluginManager | `core/plugin_manager.gd` | 发现 / 加载 / 启用 / 禁用 / 卸载 / **热重载** |
| Plugin 契约 | `core/plugin.gd` | 插件基类（由 `ModInterface` 演进） |
| PluginScene 基类 | `core/plugin_scene.gd` | 场景插件基类（由 `ModScene` 演进） |
| SceneDirector | `core/services/scene_director.gd` | 场景注册表 + 切换 + 当前场景管理 |
| EventBus | `core/services/event_bus.gd` | 全局信号总线（解耦插件间通信） |
| DataService | `core/services/data_service.gd` | `userdata/` 读写、JSON 缓存、变更通知 |
| FileWatcher | `core/services/file_watcher.gd` | 轮询式文件变更检测（热重载触发源） |
| PluginRegistry | `core/services/plugin_registry.gd` | 能力索引：按 scene id / slot 查询提供者 |
| CoreConfig | `core/core_config.json` | 内核级配置（插件根目录、日志级别等） |

> `main.gd` 从"场景加载器"退化为**引导壳**：只做窗口设置、挂载 `MainContentRoot`、把控制权交给 Kernel。`scene_map` 与三个 `preload` 常量删除。

## 5. 插件契约

### 5.1 目录结构（内置/第三方一致）

```
<plugin_root>/your_plugin/
├── plugin.json        # 清单（必需）
├── plugin.gd          # 入口脚本：extends Plugin（必需）
├── scenes/            # 场景资源（直播场景放这里）
│   └── live_scene.tscn
├── panels/            # 控制面板 UI（可选）
├── scripts/           # 其他脚本（可选）
├── assets/            # 自有资源（可选）
└── data/              # 自有数据（可选）
```

### 5.2 清单 `plugin.json`

```json
{
    "id": "your_plugin",
    "name": "你的插件",
    "version": "1.0.0",
    "author": "作者",
    "description": "一句话简介",
    "api_version": "2.0.0",
    "dependencies": [],
    "load_priority": 0,
    "hot_reload": { "enabled": true, "mode": "auto", "debounce_ms": 300 },
    "watch": ["scenes/", "scripts/", "data/"],
    "provides": {
        "scenes": [
            { "id": "your_live_scene", "name": "你的直播场景", "type": "live",
              "scene": "scenes/live_scene.tscn", "description": "直播画面说明" }
        ],
        "panels": [
            { "id": "your_panel", "name": "你的面板", "scene": "panels/panel.tscn",
              "slot": "right", "order": 10 }
        ]
    }
}
```

**能力（provides）类型**

| 能力 | 说明 | 对应现状 |
|---|---|---|
| `scenes[]` | 可切换场景（`type` ∈ `live`/`overlay`/`ui`） | 内置 3 场景 + 模组 `streaming_scenes` |
| `panels[]` | 注入控制面板的面板（含 `slot` 与 `order`） | `SceneManager`、`ModManager`、编辑器 |
| `data` | 声明自有数据目录 | `data_files` / `asset_paths` |

> 兼容性：`mod.json` 与 `streaming_scenes` 仍可被解析，映射为 `provides.scenes[type=live]`（见 §9）。

### 5.3 入口脚本 `plugin.gd`

```gdscript
extends Plugin

func get_metadata() -> Plugin.PluginMetadata:
    var m := Plugin.PluginMetadata.new()
    m.id = "your_plugin"
    m.name = "你的插件"
    return m

# 生命周期（按需重写）
func on_load() -> bool: return true        # 加载：注册资源，勿做重活
func on_enable() -> void: pass             # 启用：注册能力、连接信号
func on_disable() -> void: pass            # 禁用：断开信号、注销能力
func on_before_reload() -> void: pass      # 热重载前：保存状态
func on_after_reload() -> void: pass       # 热重载后：恢复状态
func on_unload() -> void: pass             # 卸载：释放资源
```

### 5.4 场景插件基类 `PluginScene`

`PluginScene`（由 `ModScene` 演进）为**所有**可切换场景提供统一底座，内置与第三方一视同仁：

- 身份：`plugin_id` / `scene_id` / `scene_name`
- 生命周期：`_on_scene_enter()` / `_on_scene_exit()`
- 数据：`get_current_player()` / `get_teams()` / … （经 `DataService`，不再自己拼路径）
- 信号：`player_changed` / `announcer_changed`（由 EventBus 转发）

## 6. 生命周期与状态机

```
UNLOADED
   │ discover + load
   ▼
LOADED ──enable──▶ ENABLED ──disable──▶ DISABLED ──enable──▶ ENABLED
   │                  │                     │
   │                  └──── reload ◀────────┘
   │                          (RELOADING → ENABLED)
   ▼ unload
UNLOADED           任意阶段出错 → ERROR（可手动重试）
```

- `PluginRegistry` 在 `ENABLED` 时登记能力，`DISABLED`/`UNLOADED` 时注销，保证场景列表实时准确。
- 依赖：`dependencies` 必须已 `ENABLED` 才允许启用；循环依赖直接置 `ERROR`。

## 7. 热重载设计（核心需求）

### 7.1 触发方式

| 方式 | 说明 |
|---|---|
| **自动（轮询）** | `FileWatcher` 每 `poll_interval_ms`（默认 500ms）扫描插件的 `watch` 路径 |
| **手动·全局** | 快捷键 `F5` / 控制面板「重载全部插件」按钮 |
| **手动·单插件** | 插件列表项旁「重载」按钮 |
| **开发模式** | 启动参数 `--plugin-hot-reload` 强制开启并输出详细日志 |

> Godot 4 的 GDScript 未暴露 OS 级文件监听 API，**轮询 `FileAccess.get_modified_time()` + 目录项增删比对**是运行时唯一可靠方案；变更合并经 `debounce_ms` 去抖。

### 7.2 重载管线（单插件）

```
检测到变更 ─▶ 去抖合并 ─▶ on_before_reload
    │
    ├─ 1. 资源重载：对变更文件用 ResourceLoader.CACHE_MODE_IGNORE 重新 load
    ├─ 2. 脚本重载：GDScript.reload()（运行时尽力）；失败则回退为整插件 reload
    ├─ 3. 场景重建：若变更插件正是"当前显示场景"的提供者 → SceneDirector 销毁旧实例、从磁盘重建
    ├─ 4. 重新注册：刷新 PluginRegistry 中该插件的能力
    ├─ 5. on_after_reload（恢复状态）
    └─ ▶ 广播 plugin_reloaded / scenes_updated
```

### 7.3 原子性与失败保护

- **先构建、后替换**：新实例 `instantiate()` 成功后才销毁旧实例；失败则保留旧场景并报 `ERROR`，绝不黑屏。
- 重载失败不中断其它插件；错误进入插件日志（控制面板可视）。
- 正在被"编辑中"的半成品文件（如编辑器尚未保存完）由去抖 + 校验兜底。

### 7.4 明确的能力边界（诚实声明）

| 场景 | 是否支持 | 说明 |
|---|---|---|
| 场景/纹理/字体/`.tscn` 变更 | ✅ 运行时可热重载 | 重新实例化即可 |
| 数据 `.json` 变更 | ✅ | 清缓存重读并广播 |
| 已运行节点上的脚本逻辑变更 | ⚠️ 尽力而为 | 依赖 `GDScript.reload()`；不一致时自动整插件重载 |
| 全局单例脚本签名变更 | ⚠️ 需整插件 reload | 会重建插件实例 |
| 导出后的模板/引擎级改动 | ❌ 需重启 | 引擎限制 |

> 在 **Godot 编辑器**内运行时，编辑器自带脚本重载会叠加生效，体验最佳。


## 9. 兼容与迁移策略

1. **清单兼容**：`plugin.json` 优先，缺失时回退读 `mod.json`；`streaming_scenes` 自动映射为 `provides.scenes[type=live]`。
2. **契约兼容**：`Plugin` = `ModInterface` 的演进（保留 `class_name ModInterface` 别名一版，标注 `@deprecated`）；`PluginScene` 同理保留 `ModScene` 别名。
3. **目录兼容**：`mods/` 继续作为第三方插件根目录；新增 `plugins/` 存放内置插件。二者由同一 `PluginManager` 扫描。
4. **autoload 兼容**：`ModLoader` 名称保留为 `Kernel` 的兼容别名（转发到 `Kernel`），或直接更名并在 `project.godot` 更新——**待确认（见 §11 Q4）**。
5. **数据兼容**：`userdata/*.json` 路径与格式不变，改由 `DataService` 统一提供。
6. **示例模组**：`mods/example_mod/` 升级为 `plugin.json` + `provides` 形式，作为第三方插件范本。

## 11. 已确认决策（原待确认项）

> 以下为已确认结论（审批通过），实施以此为准。

| # | 决策点 | 结论 |
|---|---|---|
| Q1 | 插件化范围 | **连编辑器也插件化**：直播场景、控制面板、选手/队伍/解说编辑器全部作为插件；core 仅保留服务 |

| Q5 | 脚本热重载边界 | 接受"尽力而为 + 回退整插件重载" |

## 12. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| Godot 运行时脚本热重载能力有限 | 逻辑改动可能需整插件重载 | 场景重建 + 失败回退；文档明确边界 |
| 轮询有 CPU 开销 | 插件多时开销上升 | 增量 mtime 比对、可调间隔、仅监听 `watch` 路径 |
| 大改架构破坏现有功能 | 程序跑不起来 | 分阶段 + 每阶段行为等价 + 无头回归 |
| `framework_cs/` 与 GDScript 内核并存 | 双轨混乱 | 本期不动 C#，契约层预留 `api_version` |

---

## 13. 验收标准

1. `main.gd` 不再包含任何具体场景的 `preload`/ID；新增场景零改核心代码。
2. 内置 3 个直播场景与第三方 `example_mod` 走**同一条**加载与切换路径。
3. 修改插件场景 / 数据 / 脚本后，无需重启即可看到变化（脚本层允许回退整插件重载）。
4. 热重载失败不黑屏、不崩溃，错误可在控制面板查看。
5. 更新后的《插件开发指南》可让开发者从零写出一个可运行插件。
